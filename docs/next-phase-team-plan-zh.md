# 下一阶段小组任务计划

规划日期：2026-10-15。代码基线：main / b832fda。
周期：三个星期；若从今天开始，建议 10 月 15–21 日、10 月 22–28 日、10 月 29 日–11 月 4 日。日期为建议，非已确认截止日。
目前没有明确人员分工，以下是四个责任方向，不假设小组有四个人；成员可兼任，但每个任务需要一位主负责人和另一位审核人。

## 阶段目标

完成可演示的持久化报价闭环：员工登录 → 读取目录 → 创建客户和草稿 → 加入产品/配件 → 保存 → 出单 → 修订 → 查看历史 → 导出 PDF。刷新或更换浏览器后仍能读取服务端保存的报价。

## 已确认现状

- 最新拉取包含配件统一算价、屏风尺寸规则、报价输出调整和合并修正。
- 前端已有报价、历史版本、本地存储、打印/PDF、照片相关代码；报价号仍由浏览器计数器生成。
- 后端当前注册 products、addons、colours、company 读取路由及 health；未实现客户/报价 API、登录、公司设置写入。
- Prisma 的 Quote 仍是单表结构，缺少交接文档要求的报价家族成交状态和版本拆分。
- 当前基线验证：23 个测试文件、191 个单元测试通过；生产构建通过。此次未运行 E2E、数据库或后端集成验证。

## 四个责任方向

### A：后端数据与报价生命周期（P0）

交付：报价家族、版本、明细和修订备注的 schema/migration；客户 CRUD；报价创建/读取/更新/列表；数据库序列分配报价号；issue、revise、deal-status、paid 更新。
验收：并发创建不重复编号；同号修订版本递增且保留历史；issued 明细不可修改；closed/abandoned 禁止编辑和出单但可改 paid、查看和重新打开。写入与状态检查在事务中完成；并发更新应有冲突响应，不能静默覆盖。
前置：先确认版本资源的 ID 语义，不能一处用家族 ID、一处用版本 ID；为现有数据准备非破坏迁移。

### B：服务端核价与权限（P0）

交付：共享或复用价格规则；保存时重新核价；登录、staff/admin 权限和受保护写接口；公司设置 PATCH。
验收：前后端在向上取档、超尺寸、N/A、网型、配件、屏风分组/数量、interlock 选项、非标颜色、GST、定金和人工改价场景一致。区分自动核价和获准人工报价，定义字段、权限和记录方式，避免重算覆盖现有手工单价功能。修改价目不能改变 issued 快照；未登录写入返回 401，staff 修改公司资料返回 403。
最新代码已移除报价中的银行卡附加费提示，后端不得因残留 cardFeePercent 字段重新计入收费。

### C：前端 API 对接（P0）

交付：统一 API client、开发代理或 CORS 配置、登录状态、目录加载、客户保存、报价保存/载入、出单/修订/成交状态和历史版本 UI 对接。
验收：服务端成为已保存报价及编号的来源；保存失败明确显示未保存并保留草稿；刷新/重新登录可取回报价；打印使用已保存的版本快照。本地草稿与服务端保存状态清晰区分。
前置：第 1 周根据 A/B 的确定契约制作 mock，后续逐个切换真接口；旧 localStorage 报价只做明确的导入或保留策略，不能无提示覆盖服务器数据。

### D：集成、回归与演示（P0）

交付：可重复启动/迁移/seed 的环境说明；合成客户和报价测试数据；CI 的单元测试、构建、关键 E2E；集成问题清单和演示脚本。
验收：新环境能启动前后端和数据库；完整走通新建→保存→出单→修订→历史→PDF；覆盖网络失败、重复提交、并发编号、权限、快照锁价和最近三项计价变更。不得把真实客户信息放进测试数据或仓库。
协作：第 1 周就定义验收用例，不能等最后一周才测试；每个开发任务由另一方向成员审核。

## 三周安排与出口

### 第 1 周：确定契约，打通最小保存链路

- 全组：首日认领 A–D 主负责人和审核人；统一 types、错误码、版本 ID、金额精度、人工报价权限。
- A：先版本 schema/migration，再客户和最小报价创建/读取/保存；序列占号及事务测试。
- B：建立价格对照用例；做登录及权限骨架，确定核价数据结构。
- C：目录 API、API client、登录及 mock 保存/读取对接。
- D：准备统一环境和合成数据；跑基线 E2E，新增服务端保存验收。
- 出口：数据库中的一张草稿能由页面保存并刷新取回，编号由数据库产生；契约中的版本与状态冲突已解决。

### 第 2 周：完成报价业务闭环

- A：issue/revise/history/deal-status/paid，事务与并发保护。
- B：完整服务端核价、金额快照、人工改价约定、公司资料权限。
- C：真实报价 API 替换 mock，完成列表/历史/状态操作和保存失败反馈。
- D：每天跑主流程及计价回归；记录并推动修复阻塞问题。
- 出口：能够登录后创建客户、保存报价、出单、同号修订、查历史；权限和锁价由服务端执行。

### 第 3 周：稳定、验收和交接

- 前半周：全组修复集成问题；D 验证并发、断网/重试、旧草稿、权限和 PDF。
- 后半周：冻结新功能，完成完整演示、环境重建验证、部署说明和已知问题记录。
- 发布出口：核心验收全部通过；没有数据丢失、重复报价号、错误金额、未授权写入或已出单被改价的问题。

## 范围控制

P1：公司设置编辑完善、旧本地报价导入工具、搜索/筛选体验优化。在 P0 闭环达标后安排。
P2：照片服务端对象存储、Excel 导入持久化、目录管理扩展；本阶段不承诺交付。客户门户、在线支付、邮件、财务系统对接不纳入本阶段。
若第 1 周保存链路未打通，立即压缩 P1/P2，保留持久化、核价、版本、权限和回归。
